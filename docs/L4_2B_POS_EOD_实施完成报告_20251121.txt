二、实际修改内容概览

1. 删除幽灵函数 calculate_eod_totals()

- 文件：store_html/pos_backend/helpers/pos_helper.php
- 改动：
  - 完全删除了 calculate_eod_totals() 函数定义及内部已熔断的异常逻辑。
- 目的：
  - 该函数曾引用不存在的 pos_invoice_payments 表，后来虽已改为 “DEPRECATED” 异常，但仍属于幽灵代码；
  - 删除后，仓库中不再出现该符号，避免未来维护者误用。
- 验证：
  - 全局搜索确认无任何调用；
  - PHP 语法检查通过。

→ 对应设计文档中的 ISSUE-POS-DB-001：状态从“已熔断，待清理”升级为“已清理”。

2. 补全正常关班写入字段，对齐强制关班行为

核心目标：让 handle_shift_end（正常关班）写入 pos_shifts 时，补齐以下字段：

- expected_cash：理论现金
- cash_variance：实点现金与理论现金的差值
- payment_summary：按支付方式分解的 JSON

2.1 正常关班 handle_shift_end()

- 文件：store_html/html/pos/api/registries/pos_registry_ops_shift.php
- 核心改动：
  - 读取当前班次信息（shift）和当前时间 now_utc；
  - 调用 compute_expected_cash() 计算 expected_cash；
  - 调用 getInvoiceSummaryForPeriod($pdo, $store_id, $shift['start_time'], $now_utc_str) 获取支付分解：
    - $invoice_summary['payments'] 形如：{"Cash": xx, "Card": yy, "Platform": zz}
  - 计算：
    - cash_variance = counted_cash - expected_cash
  - 更新 pos_shifts 时写入：
    - end_time
    - status='ENDED'
    - counted_cash
    - expected_cash
    - cash_variance
    - payment_summary（JSON）

- 特点：
  - 复用既有聚合函数 getInvoiceSummaryForPeriod()，不重新写 SQL；
  - expected_cash 仍由 compute_expected_cash() 统一产出，避免破坏其他调用方。

2.2 强制关班 handle_shift_force_start()

- 文件：同上
- 核心改动：
  - 在原有逻辑基础上，同样调用 getInvoiceSummaryForPeriod() 获取 payments；
  - payment_summary 结构与正常关班保持一致，并额外附加元数据字段：
    - "_force_closed_by": 关闭人姓名
    - "_force_closed_note": 简短说明，例如 "Shift was forcibly closed due to EOD cutoff"
  - 其他字段（expected_cash / cash_variance）保持原有算法不变。

- 结果：
  - 正常关班与强制关班在 pos_shifts 中写入的核心财务字段完全对齐；
  - 强制关班多记录了管理员信息，便于事后审计。

三、数据来源与计算逻辑（与设计对齐情况）

1. SSOT 架构保持不变

- 交易 SSOT：pos_invoices
- 班次快照：pos_eod_records
- 日结快照：pos_eod_reports

本次改动没有动任何 Schema，也没有改动 EOD 的聚合算法，只是在“写回 pos_shifts 字段”时复用已有聚合结果。

2. 关键字段计算保持对齐

- expected_cash：
  - 仍由 compute_expected_cash() 生成（不改返回结构）；
  - 公式不在此展开，参考原实现；
  - 仅保证正常关班也写入该值。

- cash_variance：
  - cash_variance = counted_cash - expected_cash
  - 正数：长款；负数：短款。

- payment_summary：
  - 统一来源：getInvoiceSummaryForPeriod() 返回的 ['payments']；
  - JSON 结构示例：
    - 正常关班：
      {"Cash": 23.50, "Card": 8.50, "Platform": 0.00}
    - 强制关班：
      {"Cash": 23.50, "Card": 8.50, "Platform": 0.00,
       "_force_closed_by": "Admin",
       "_force_closed_note": "Shift was forcibly closed due to EOD cutoff"}
  - 以 "_" 前缀标记管理元数据字段，便于消费方识别/忽略。
